# Sunset Rush: Overdrive — Full Audit (2026-09-09)

Triggered by user report on the live build (https://thearchitectit.github.io/sunset-rush/):
**"the firing doesn't work and the game doesn't say on screen very well."**

Scope: code quality, controls/discoverability, weapon acquisition and firing
(keyboard + touch), collision/gameplay behavior, responsive layout, HUD
readability, accessibility, audio lifecycle, performance, deterministic state,
offline/download integrity, tests, CI, DevGate integration, and every archived
OpenSpec requirement vs delivered behavior.

Method: static review of `index.html` (1032 lines) and all gates; local gate
runs; live GitHub Pages build exercised with **real browser input** (mouse
clicks, keyboard key presses, touch taps) in a cloud browser at desktop
(1280x713) and mobile (390x844, iPhone UA) viewports; plus a local headless
Chrome harness driving the game over the Chrome DevTools Protocol with trusted
`Input.dispatchKeyEvent` / `Input.dispatchTouchEvent` events (not test hooks).
Screenshots inspected as pixels.

## Verdict

The user's report is confirmed and rooted in three design/implementation
defects, one process defect, and one latent CI defect. The firing *mechanism*
works; firing *availability and feedback* do not. Every archived spec
requirement passes its headless test, and the game still fails the player —
the specs and the validation harness had blind spots (enumerated below).

## Critical findings

### F1. No weapon at race start; fire is silently inert — CONFIRMED LIVE
`reset()` leaves `weapon=null, ammo=0`. Weapons exist only inside randomly
spawned amber crates (45% of pickup rolls, one pickup every 2.2-3.8s, random
lane). `fireWeapon()` returns early with no weapon, producing **no projectile,
no message, no sound, no HUD change**. The HUD weapon box shows a lone "-".

Live evidence (desktop, real input): started a race with a real mouse click,
pressed real Space five times → `proj:0`, `#msg` empty, HUD weapon "-".
Live evidence (mobile, real input): two real FIRE pad taps → same result.
With a weapon equipped (setup via hook), the same real inputs fire immediately
(pad tap → `proj:1`, ammo 14→13) — the input path is fine; availability and
feedback are not.

A bot that *deliberately steers into crates* still found no weapon within the
45s level-1 timer in 1 of 10 seeded runs (first-equip times otherwise
4.4-15.6s). A player who does not know crates carry weapons — nothing on
screen says so — races the whole level unable to fire. This is the reported
"the firing doesn't work."

### F2. Touch slide-steering never transfers zones — CONFIRMED REAL TOUCH
`pointermove` recomputes the role from `e.target`, but touch pointers are
implicitly captured to their `pointerdown` target, so `e.target` never changes
while sliding. A finger that starts on the left zone steers left forever,
even dragged onto the right zone. Measured with true CDP touch events:
left hold steered playerX 0 → -0.436; sliding the same finger to the right
zone continued to -1.736 (never right). Players must lift and re-tap to
change direction — the natural thumb-drag gesture fights them.

### F3. On-screen communication and legibility — CONFIRMED LIVE/PIXELS
- Mobile HUD: 9px labels, 11px values, 64px armor bar (computed styles at
  390px width). Six boxes wrap to two rows.
- Weapon state is "-" with no hint that crates carry weapons; no in-race
  control reminder; countdown shows "3/2/1/GO!" but never "SPACE = FIRE".
- The touch overlay (BRAKE label, steer arrows, FIRE pad) renders *behind and
  around* the title menu, visible through the translucent overlay.
- `sr-pre-hud` delivered the required fields, but nothing in spec or tests
  constrained legibility. This is the reported "doesn't say on screen well."

## High findings

### F4. CI `gates` workflow has been red on main since the Overdrive merge
The Semantic scan step fails in CI: `semantic-scan.mjs` needs the `typescript`
compiler API, installed locally by the prior author but never in
`.github/workflows/ci.yml`. GitHub runs 34389320216 (342ebd6) and 34389338580
(main 336bf95) both = failure at step "Semantic scan". Clean-checkout repro:
exit 1, "cannot load the typescript compiler API". The merge report claimed
gates passed — they passed only on a dirty local machine. Pages deploys
through a separate workflow, so the game shipped anyway.

### F5. Latent next CI failure: regression_check --all has no diff base
`--all` diffs `HEAD~20...HEAD` when no tag exists; the repo has 4 commits and
no tags, so the step errors ("unknown revision") as soon as F4 is fixed.
Fix: tag the current release (v2.0.0 at 336bf95) so the gate has a base.

### F6. Downloaded export can boot into a stale GAME OVER screen
`downloadSelf()` serializes live `document.documentElement.outerHTML`,
including runtime class flips. Exporting from the game-over screen yields a
file whose start screen has `hidden` and whose game-over screen is visible,
with stale final stats. Confirmed by serializing at game-over in a real
browser. Violates the spirit of sr-pre-download (the export is not a clean
copy of the game).

## Medium findings

### F7. Determinism is frame-rate coupled — render consumes gameplay RNG
`render()` calls the shared seeded `rng()` (speed lines, shake translation,
muzzle flash radius, nitro flames). 900 identical input ticks with vs without
interleaved renders produce divergent gameplay state (different mob/pickup
positions and kinds, different particle counts). The sr-pre-determinism test
never renders between ticks, so the coupling is invisible to it. Two players
at 30fps and 60fps cannot replay the same run; the spec's "fixed seed
reproduces the same run" only holds for renderless replays.

### F8. Fire input is frame-polled; sub-frame taps drop shots
`input.fire` is level-sampled inside `update()`. A real trusted Space tap with
~0ms hold (keydown+keyup between two rAF ticks) fired **nothing** with the
blaster equipped and 14 ammo; a 400ms hold fired 3 shots; human-speed 80ms
taps at 59.5fps fired 6/6. On 20-30fps mobile hardware, real quick taps can
fall between frames. Fire should be edge-captured on keydown/touchstart.

### F9. updateHUD runs twice per frame
`step()` calls `updateHUD()` and `frame()` calls `step()` then `updateHUD()`
again — the same duplicated-call-site shape as registry entry FAIL-2026090903
(traffic). Wasted DOM writes every frame.

### F10. Traffic freezes during the countdown
The countdown branch returns before `updateTraffic(dt)`, so cars hang
motionless for 3.2s in full view at every race start.

## Low findings

- F11. `keysHeld` map is written, never read (dead code).
- F12. `lastBeep` is not reset in `reset()`; a restarted countdown can skip
  its first tick beep.
- F13. `ptrRoles` is not cleared on game over; a finger held through the
  wreck carries a stale role into the next race until pointerup.
- F14. `downloadSelf` swallows all errors silently (silent-success shape).
- F15. Accessibility: `.btn` has no `:focus-visible` style; the canvas has no
  accessible name; `#msg` is not announced to screen readers. Buttons are real
  `<button>`s and Enter/Space starts the race, which is good.
  `user-scalable=no` remains an accepted game tradeoff (documented).

## Validation gaps (why gates were green while the game was broken)

- G1. Every input test calls `window.__game` hooks or invokes DOM listeners
  directly; nothing exercised trusted browser input end-to-end. F1/F2/F8 slip
  through.
- G2. No touch-drag (pointermove) test exists.
- G3. No export-content integrity test.
- G4. The determinism test never interleaves `renderOnce()`.
- G5. No screenshot or computed-style readability check anywhere.
- G6. Release process never checked the CI run on the merge commit (F4/F5).

## Remediation

All findings map to normative requirements and tasks in OpenSpec change
`openspec/changes/remediate-fire-and-readability/` (proposal, design, tasks,
spec deltas for `combat-weapons` and `presentation-offline`). Validation now
includes a zero-dependency CDP end-to-end suite (`tests/e2e-chrome.mjs`) that
drives the real file in headless Chrome with trusted keyboard and touch
events, plus pixel screenshots and computed-style legibility assertions.
